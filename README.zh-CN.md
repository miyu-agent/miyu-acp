# ACP 智能体模型供应商（acp）

> <sub>本文档由 Anthropic 的 Claude Opus 5.5 生成。</sub>

`acp` 是 Miyu 的一个软件包。安装之后，你可以把支持 [Agent Client Protocol](https://agentclientprotocol.com)（ACP）的智能体程序当作模型供应商来用：Claude Code（通过它的 ACP 适配器）、Google Antigravity、Gemini CLI、Codex、OpenCode，以及 [ACP 官方登记表](https://agentclientprotocol.com/get-started/registry) 里的其他智能体。Miyu 的每一次模型调用都会交给你选的智能体，使用你在那个智能体里已经登录的账号。

智能体在这里只负责思考和回答。读文件、运行命令、修改文件这些工具仍然由 Miyu 执行，所以权限、确认和撤销都和使用其他模型时一样。智能体能不能使用它自带的工具是一项设置；默认情况下，它只能使用自带的只读搜索和网页抓取。

这个软件包支持 Linux 和 macOS，不支持 Windows。

## 安装前的准备

安装这个软件包之前，需要准备好以下几项：

- Miyu 核心需要 2026.11.0-rc.2.6 或更新的版本。
- 登记表里很多智能体通过 `npx` 或 `uvx` 运行。要使用它们，需要先安装 Node.js（用于 `npx`）或者 uv（用于 `uvx`）。登记表以下载包形式提供的智能体不需要额外准备：你第一次使用时，软件包会自动下载。
- 在你要使用的智能体里完成登录。软件包不会替你登录，所以需要先用智能体自己的程序登录一次，就像在编辑器里使用它之前一样。例如，Claude Code 适配器使用的是本机 Claude Code 的登录。

## 安装和选择模型

运行：

```bash
miyu pkg install acp
```

安装时 Miyu 会询问你是否批准这个软件包的两项能力：提供模型驱动，以及联网（软件包要下载登记表和智能体，智能体也要连接它们自己的服务）。

安装完成后，模型供应商列表里会多出一家 `ACP 智能体`（编号是 `acp`）。它的模型就是各个智能体：

- `acp/<智能体>` 使用这个智能体自己的默认模型，例如 `acp/claude-acp`、`acp/gemini`。智能体的编号就是官方登记表里的编号。
- `acp/<智能体>/<模型>` 选用这个智能体提供的某一个模型，例如 `acp/claude-acp/sonnet`。一个智能体用过一次以后，`/model` 里会列出它报告的模型。Claude Code 适配器报告的模型里既有简称（`opus`、`sonnet`、`haiku`），也有带版本号的全名（例如 `claude-haiku-4-5-20251001`）。简称总是指向当前这一代的模型，全名固定指向那一个版本，所以 `haiku` 和 `claude-haiku-4-5-20251001` 不是同一个模型，上下文窗口也可能不一样。

模型列表里是登记表中所有能在你的系统上安装的智能体。第一次使用以下载包形式提供的智能体时，软件包会下载它，按照登记表里写的 SHA-256 核对，再解压到软件包自己的数据目录里；比较大的智能体需要等一会儿。登记表里没有写校验和的下载包一律不安装。登记表本身每天最多重新获取一次；获取不到时，使用上一次保存的那一份。

### 设置项

设置项可以在设置页的 `软件包` 里填写：

| 设置 | 键 | 默认值 | 说明 |
|---|---|---|---|
| 对方自带的工具 | `acp.own_tools` | 只用 Miyu 的工具 | 除了 Miyu 的工具以外，是否允许智能体使用它自带的工具，见下面的「对方自带的工具」 |
| 对话结束后进程保留时长（秒） | `acp.keep_seconds` | 600 | 一轮对话结束后，智能体进程会保留这么久，等待同一段对话的下一轮。填写 0 表示不保留 |
| 工具调用超时时长（秒） | `acp.tool_wait_seconds` | 3600 | 一次交给 Miyu 的工具调用最多等待这么久。Miyu 执行工具的时间和等待你确认的时间都计算在内 |
| 其他智能体 | `acp.agents` | 无 | 官方登记表以外的智能体，见下文 |

### 登记表以外的智能体

要使用登记表里没有的智能体，可以在 `其他智能体` 里添加。每一项有一个名字和一行启动命令：

```text
名字：     my-agent
启动命令： MY_AGENT_MODE=acp ~/bin/my-agent --acp
```

启动命令写成一行：程序和参数，用空格隔开。环境变量写在最前面，格式是 `名字=值`。含有空格的词用引号括起来；开头的 `~` 表示家目录。这个命令会直接运行，不经过 shell。添加以后，把模型写成 `acp/my-agent` 就能使用它。如果名字和登记表里的某个智能体相同，以你添加的这一项为准。

### API 密钥

有的智能体也可以用 API 密钥登录（例如 Antigravity 的 Gemini API 密钥方式）。如果你在 `ACP 智能体` 这家供应商的设置里填写了密钥，智能体提供这种登录方式时，软件包就会用它登录。

## 对方自带的工具

大多数智能体都有自己的工具。`对方自带的工具` 这项设置决定怎样处理它们：

- **只用 Miyu 的工具**（默认）：智能体自带的只读搜索、网页抓取和思考可以使用，Miyu 会在时间线上把它们显示为供应商侧工具。智能体请求运行其他工具（修改文件、运行命令等）时，软件包一律拒绝。对于 Claude Code 适配器和 Antigravity，软件包在打开会话时还会关掉它们的其他工具。
- **也放行对方的工具**：智能体请求运行它自带的工具时，Miyu 会弹出它自己的确认框询问你，你可以选择「允许这一次」或者「拒绝」。软件包打开会话以后会把智能体切换到「每次都先询问」的权限模式（Claude Code 适配器、Gemini CLI、Antigravity 的 `default`），不沿用你在本机给这个智能体程序设置的权限模式：即使你平时让 Claude Code 跳过确认，经过 Miyu 使用时它也会先询问。这些工具会直接运行命令、修改文件，不在 Miyu 的沙盒和权限管理之内。没有人能确认的会话（群聊、陌生人的私聊这类）里，这种请求一律拒绝；会话处于只读状态时，修改文件、运行命令的请求也会被拒绝。这一档需要支持这种确认的 Miyu 核心；核心太旧时，Miyu 会按照「只用 Miyu 的工具」处理，并在这个软件包的日志里记录一句。

两项设置下，软件包都会这样切换权限模式。即便如此，智能体仍有可能不先请求就运行某个会修改东西的工具，例如你在本机给它设置的允许规则（Claude Code 的 `permissions.allow`）放行了这个工具，或者这个智能体没有「每次都先询问」的模式。这时 Miyu 仍然会在时间线上显示这个工具，在结果前面写明「未经确认已执行」，软件包也会在日志里记录一条警告。读取文件、搜索这类不修改东西的工具不会这样标注。

## 使用须知

使用这个软件包时，需要注意以下几点：

- **接着对话**：同一段对话的下一轮会交给仍然开着的智能体会话，只发送新增的内容。如果接不上（例如核心重启、压缩或撤销以后、切换了模型或人格），软件包会打开一个新的智能体会话，把完整的历史作为一段文字发给它。
- **同时最多保留 4 个智能体会话**，每个会话有自己的智能体进程。超过时，最久没有使用的那个会被结束。
- **一次性的请求用完就结束。** Miyu 为会话起标题这类一次性请求，没有系统提示词、没有工具、只有一句话，不会再有下一轮。软件包为它打开的智能体会话在回答完以后立即结束，不占用上面的 4 个名额。
- **智能体会自己保存会话记录。** 智能体通常把会话保存在它自己的数据里，所以 Miyu 打开的会话也会出现在智能体的历史记录中。这些会话都使用软件包数据目录里同一个空的工作目录。
- **图片和文件**：这一轮的图片、音频和其他文件，在智能体能接收时会作为 ACP 内容一起交过去。之前轮次里的图片改用文字说明。
- **用量**：智能体报告了这一轮的词元数时，Miyu 会记录下来，同时记录这一轮结束时上下文用了多少。没有报告词元数的智能体记为「没有报告」。显示的金额只是参考，因为你实际消耗的是那个智能体自己的订阅或额度。
- **没有登录、额度用完、限流**：软件包会根据智能体自己的报错原文进行分类，再报告给 Miyu。智能体需要登录时，报错会说明这一点，并列出智能体提供的登录方式。

## 故障排查

下表列出常见的现象、原因和处理方法：

| 现象 | 原因和处理方法 |
|---|---|
| `… needs you to log in first` | 用智能体自己的程序登录以后再试。如果智能体提供 API 密钥方式，也可以在供应商设置里填写密钥 |
| `… runs through npx, which was not found on PATH` | 安装 Node.js。如果是 `uvx`，安装 uv |
| `… cannot be installed on …` | 登记表里没有适合你的系统的、带校验和的下载包，也没有 `npx` 或 `uvx` 包 |
| `… does not match the registry's SHA-256` | 下载到的文件和登记表描述的不一致，所以没有安装。过一会儿再试；如果一直这样，请告诉这个智能体的作者 |
| `… does not offer the model …` | 智能体编号后面的模型名不是这个智能体提供的。报错里列出了它提供的模型 |
| 工具已经运行过了，Miyu 却又把整段历史重新发送了一遍 | 智能体先放弃了等待工具结果，或者核心重启了。这是正常现象，只是那一次请求会多消耗一些额度 |

软件包自己的日志保存在数据目录的 `var/log/acp/stderr`，里面记录了智能体请求运行哪些工具、软件包怎样回答，以及哪些会话被作废并重新开始。

## 开发

开发时运行格式检查、静态检查和测试：

```bash
cargo fmt --all --check
cargo clippy --all-targets -- -D warnings
cargo test          # 集成测试使用假的智能体（tests/fake_acp.py，需要 python3），不会启动真的智能体
```

这个软件包使用 AGPL-3.0-or-later 许可证。
