# ACP agents as model providers (acp)

> <sub>This document was generated by Anthropic's Claude Opus 5.5.</sub>

`acp` is a Miyu package. Once it is installed, you can use agent programs that speak the [Agent Client Protocol](https://agentclientprotocol.com) (ACP) as model providers: Claude Code (through its ACP adapter), Google Antigravity, Gemini CLI, Codex, OpenCode and the other agents in the [official ACP registry](https://agentclientprotocol.com/get-started/registry). Every model call Miyu makes is handed to the agent you chose, using the account you are already logged into in that agent.

Here the agent only does the thinking and answering. Tools such as reading files, running commands and editing files are still run by Miyu, so permissions, confirmations and undo work the same as with any other model. Whether the agent may also use its own tools is a setting; by default it may only use its read-only search and web fetching.

This package supports Linux and macOS, not Windows.

## Before you install

Before you install this package, have these things ready:

- The Miyu core must be 2026.11.0-rc.2.6 or newer.
- Many agents in the registry run through `npx` or `uvx`. To use them, install Node.js (for `npx`) or uv (for `uvx`) first. Agents that the registry ships as a download need nothing extra: the package downloads them the first time you use them.
- Log in to the agent you want to use. The package never logs in for you, so do it once with the agent's own program, the same way you would before using it in an editor. For example, the Claude Code adapter uses the login of your local Claude Code.

## Installing and choosing a model

Run:

```bash
miyu pkg install acp
```

During installation, Miyu asks you to approve the package's two capabilities: providing a model driver, and network access (the package downloads the registry and the agents, and the agents connect to their own services).

After installation, the model provider list has one more entry, `ACP agents` (id `acp`). Its models are the agents themselves:

- `acp/<agent>` uses the agent with its own default model, for example `acp/claude-acp` or `acp/gemini`. The agent ids are the ones in the official registry.
- `acp/<agent>/<model>` picks one of the models the agent offers, for example `acp/claude-acp/sonnet`. After you have used an agent once, `/model` lists the models it reported.

The model list contains every registry agent that can be installed on your system. The first time you use an agent that the registry ships as a download, the package downloads it, checks it against the SHA-256 written in the registry, and unpacks it into its own data directory; this can take a while for large agents. Downloads without a checksum in the registry are never installed. The registry itself is fetched at most once a day; when it cannot be fetched, the last copy is used.

### Settings

You can fill in the settings under `Packages` on the settings page:

| Setting | Key | Default | Description |
|---|---|---|---|
| Agent's own tools | `acp.own_tools` | Only Miyu's tools | Whether the agent may run its own tools besides Miyu's; see "The agent's own tools" below |
| Process retention after a turn (seconds) | `acp.keep_seconds` | 600 | After a turn ends, the agent process is kept this long, waiting for the next turn of the same conversation. 0 means it is not kept |
| Tool call timeout (seconds) | `acp.tool_wait_seconds` | 3600 | How long a tool call handed to Miyu may take at most. The time Miyu spends running the tool and the time spent waiting for your confirmation both count |
| Other agents | `acp.agents` | none | Agents that are not in the official registry; see below |

### Agents outside the registry

To use an agent that is not in the registry, add it under `Other agents`. Each entry has a name and one command line:

```text
Name:     my-agent
Command:  MY_AGENT_MODE=acp ~/bin/my-agent --acp
```

The command line is the program and its arguments, separated by spaces. Environment variables come first, as `NAME=value`. Put quotes around words that contain spaces; a leading `~` means your home directory. The command is run directly, not through a shell. You then use the agent as the model `acp/my-agent`. An entry with the same name as a registry agent replaces that registry agent.

### API keys

Some agents can also log in with an API key (for example the Gemini API key method of Antigravity). If you fill in a key in the settings of the `ACP agents` provider, the package logs in with it whenever the agent offers such a method.

## The agent's own tools

Most agents come with tools of their own. The setting `Agent's own tools` decides what happens to them:

- **Only Miyu's tools** (the default): the agent's read-only search, web fetching and thinking are allowed, and Miyu shows them in the timeline as provider-side tools. Whenever the agent asks for permission to run anything else (editing files, running commands and so on), the package refuses. For the Claude Code adapter and Antigravity, the package also switches their other tools off when it opens a session.
- **Also allow the agent's tools**: when the agent asks for permission to run one of its own tools, Miyu asks you, with the options the agent offers. These tools run commands and change files directly, outside Miyu's sandbox and permissions. Miyu can only ask you in a session where you can answer questions; in other sessions, such as group chats, the request is refused.

Whatever the setting, an agent might run one of its tools without asking first. Miyu still shows such a tool in the timeline, and the package writes a warning to its log.

## Notes on use

When you use this package, keep the following points in mind:

- **Continuing a conversation**: the next turn of a conversation goes to the agent session that is still open, and only the new content is sent. If it cannot continue (for example after the core restarts, after compaction or undo, or after switching the model or persona), the package opens a new agent session and sends the full history to it as one block of text.
- **At most 4 agent sessions are kept at the same time**, each with its own agent process. Beyond that, the one unused for the longest time is stopped.
- **The agent keeps its own session history.** Agents usually store their sessions in their own data, so sessions opened by Miyu appear in the agent's history too. They all use the same empty working directory inside the package's data directory.
- **Images and files**: images, audio and other files from the current turn are passed on as ACP content when the agent accepts them. Images from earlier turns are described in text instead.
- **Usage**: when the agent reports token counts for a turn, Miyu records them, together with how full the context was at the end. Agents that report no token counts are recorded as "not reported". The amount shown is only a reference, because what you actually use up is that agent's own subscription or quota.
- **Not logged in, quota exhausted, rate limits**: the package classifies these from the agent's own error text and reports them to Miyu. When the agent needs a login, the error says so and names the login methods the agent offers.

## Troubleshooting

The table below lists common symptoms, their causes and what to do:

| Symptom | Cause and fix |
|---|---|
| `… needs you to log in first` | Log in with the agent's own program, then try again. You can also fill in an API key in the provider settings if the agent offers an API key method |
| `… runs through npx, which was not found on PATH` | Install Node.js. For `uvx`, install uv |
| `… cannot be installed on …` | The registry has no download with a checksum, no `npx` package and no `uvx` package for your system |
| `… does not match the registry's SHA-256` | The download is not the one the registry describes, so it was not installed. Try again later; if it keeps happening, report it to the agent's authors |
| `… does not offer the model …` | The model name after the agent id is not one the agent offers. The error lists the ones it does |
| A tool has already run, but Miyu resends the whole history | The agent stopped waiting for the tool, or the core restarted. This is normal; that request just uses more quota |

The package's own log is kept at `var/log/acp/stderr` in the data directory. It records which tools the agent asked to run, what the package answered, and which sessions were discarded and started over.
